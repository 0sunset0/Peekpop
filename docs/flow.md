# Flow — Peekpop (v0)

5개 화면, 선형 흐름. tech-critic-lead 게이트(2026-08-29)로 온보딩 캐러셀과 브러시 보정 UI를 다음 버전으로 미뤘다 — 근거는 `docs/prd.md`의 "v0 스코프 결정", 각 화면 결정의 기술적 배경은 `docs/ade.md` 참고.

1. **메인** — "사진 선택하기" 버튼 + 예시 사진 1장 + 안내 문구("폰 카메라 앱을 켜고, 화면에 인물이 보이게 찍어주세요"). 온보딩 캐러셀 없음, 이 한 화면이 안내를 겸한다 → 2
2. **사진 선택** — iOS 표준 시트(카메라/앨범). 앨범 선택은 권한 불필요. 선택 즉시 확인 없이 → 3
3. **화면 경계 확인** — 대상은 "폰 화면 전체"가 아니라 **카메라 UI(상태바·버튼) 제외, 사진이 보이는 부분만**. Vision 자동 검출로 4꼭짓점 프리필(실패 시 인물 사진 비율의 기본 사각형), 사용자가 드래그로 확정. 레이아웃은 사진(+사각형 조정 영역) / 안내 문구 카드 / "확인" 버튼을 세로로 겹치지 않게 분리한다(디자인 리뷰 반영 — 안내 카드가 조정 중인 사진 위에 떠 있으면 내용이나 핸들을 가릴 수 있음). 안내 문구는 "노란 점을 움직여서 폰 화면 테두리에 맞춰주세요"(표면색 카드 배경 85% 불투명도) — 기하학 용어("꼭짓점"/"사각형") 대신 사용자가 실제로 보는 대상(폰 화면)을 기준으로 안내한다. 뒤로가기 가능(→2). "확인" → 4
4. **처리 (로딩)** — 3의 영역으로 크롭 → AI로 인물 마스크 생성 → 결과가 degenerate(커버리지가 임계치 밖 — 거의 비어있거나 거의 전체)하면 브러시 보정 없이 곧장 에러 화면("다시 시도해주세요" 단일 버튼 → 2)으로. degenerate가 아니면 컷아웃 확대·재배치(사각형 기울기 반영)·그림자 합성까지 이어서 진행 → 5
5. **결과** — 자동 배치된 결과를 보여주고, **저장 전에 드래그(이동)/핀치(크기)/두 손가락 회전으로 배치를 직접 조정**할 수 있다(조정할 때마다 즉시 재합성해 미리보기에 반영 — Vision을 다시 부르지 않아 빠름). 조정 UI는 브러시로 마스크 자체를 고치는 것과는 다르다(그건 여전히 v0 범위 밖) — 이미 오려낸 피사체를 어디에 얼마나 크게 놓을지만 조정한다. 하단은 **저장**(이 화면의 메인 액션, 꽉 찬 primary 버튼)과 **공유하기**(그 옆 작은 원형 아이콘 버튼, 같은 줄)만 두어 "이 사진으로 뭘 할지"에 집중시킨다. 화면 상단 모서리에 나가는 버튼 두 개를 역할을 나눠 배치한다: **좌상단 `<`**는 같은 사진을 유지한 채 경계 사각형만 다시 맞추도록 3번(화면 경계 확인)으로 돌아가고, **우상단 X**는 사진 선택부터 완전히 새로 시작하도록 1번(메인)에 머무른다. 저장 탭 시 화면 하단에 "저장되었어요" 토스트가 잠깐 떴다 사라짐. **X → 1 (메인 화면에 머무름 — startOver()/retryFromError()와 달리 피커를 자동으로 열지 않는다, 사용자가 직접 "사진 선택하기"를 눌러야 함)**. 경계 확인 화면의 `<`와 에러 화면의 "다시 시도"는 여전히 2(사진 선택)로 바로 돌아간다 — X만 예외적으로 메인에 머무른다.

## 색상 (디자인 리뷰 반영)
배경은 순정 검정(`#000000`) 유지 — 사진이 화면을 꽉 채우는 몰입형 뷰어 UX(카메라/사진 뷰어와 동일 패턴)이고, "꺼진 폰 화면에서 튀어나온다"는 컨셉과도 맞는다. 포인트 컬러는 코랄 `#FF5C7A`(`Color.peekpopAccent`) — Primary 버튼(각 화면의 메인 액션: 사진 선택하기/확인/저장/다시 시도)과 처리중 화면 스피너에만 쓴다. 공유·홈으로 같은 보조 액션에는 일부러 안 써서 "이게 메인 액션이다"라는 위계 신호를 유지한다. 순정 검정과 구분되는 표면색으로 `#1C1C1E`(`Color.peekpopSurface`)를 결과 화면 저장 토스트 배경에 쓴다(기존엔 `Color.black.opacity(0.85)`라 배경과 거의 안 구분됐음). 경계 확인 화면의 노란 핸들/선은 기능적 용도(사진 위에서 항상 눈에 띄어야 함)라 예외로 원색 유지.

## 환경/예외

- 다크 테마 고정(시스템 설정 안 따름), 세로 화면 고정.
- 카메라 권한 거부(2번, 촬영 선택 시) → 설정 이동 안내.
- 사진 저장 권한 거부(5번, "저장" 탭 시) → 설정 이동 안내. (앨범에서 고르는 건 권한 자체가 없음)
- Vision 실제 오류(인식 실패가 아닌 예외) 또는 마스크 degenerate → "다시 시도" 단일 버튼 화면 → 2번으로. 두 경우 모두 같은 에러 화면 재사용.
- 접근성(VoiceOver, Dynamic Type 등) v0 미지원, iOS 기본값만.

## 공통 컴포넌트
Primary 버튼(CTA 전 화면 공용), 로딩 인디케이터(4 전용), 안내 문구 스타일(1·3 공용). Primary 버튼 좌우 여백은 모든 화면에서 24pt로 통일한다(기존엔 화면마다 24/32/48pt로 제각각이라 화면별 CTA 존재감이 달라 보였음, 디자인 리뷰 반영).

## 타이포 위계 (디자인 리뷰 반영)
안내 문구·버튼 라벨·보조 힌트 텍스트가 다 비슷한 굵기/크기라 구분이 안 된다는 지적을 반영해 3단으로 정리했다:
1. **안내/지시 문구**(각 화면에서 지금 뭘 해야 하는지 알려주는 문구 — 메인·경계확인·처리중·에러 메시지) → `.body`(iOS 표준 본문 크기, 17pt regular), `lineSpacing(4)`, 흰색 100%. (`.title3.semibold` → `.title3.medium` → `.body`로 두 차례 더 낮췄다 — 커스텀 크기보다 "정해진 본문 글씨 크기"가 낫다는 피드백. 버튼 라벨(`.headline`, 17pt semibold)과는 이제 크기가 아니라 굵기로 구분된다.)
2. **버튼 라벨**(Primary 버튼) → `.headline`(기존 그대로, `PrimaryButtonStyle`).
3. **보조 힌트**(결과 화면의 조작 안내 문구) → `.footnote`, 흰색 60% 투명도.

이 위계는 결과 화면뿐 아니라 앱 전체(메인·경계확인·처리중·에러)에 일관 적용한다.
