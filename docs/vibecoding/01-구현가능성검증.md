# 1. 구현 가능성 검증 — Peekpop

작성일: 2026-08-29
상태: 완료

## 요구사항 (검증 대상)

Peekpop의 핵심 기능이 온디바이스 컴퓨터 비전만으로 실제 구현 가능한지 검증한다. 구체적으로:

- FR1: 사진 속 "폰 화면" 영역을 특정할 수 있어야 한다 (자동 검출 또는 수동 지정).
- FR2: 화면 안에 표시된 인물/오브젝트를 배경에서 분리해 오려낼 수 있어야 한다 (누끼).
- FR3: 오려낸 오브젝트를 화면 경계 밖으로 확대·재배치해 합성할 수 있어야 한다.
- FR4: 위 처리가 전부 온디바이스에서 가능해야 한다 (네트워크 호출 불필요).

## 검증 방법

macOS Swift 커맨드라인 스파이크(버릴 프로토타입 코드)로 Apple Vision 프레임워크의 실제 API를 실사용 예상 사진 4장에 대해 실행해 결과를 관찰했다.

- 사용 API: `VNDetectRectanglesRequest`, `VNDetectFaceRectanglesRequest`, `VNGenerateForegroundInstanceMaskRequest`, `VNGeneratePersonSegmentationRequest`, `VNGeneratePersonInstanceMaskRequest`
- 샘플 4장:
  1. 스티커·장식이 합성된 트렌드 "완성본" 참고 이미지
  2. 실제 후보 원본 사진 — 폰(레드 케이스)이 정면으로 서 있고 화면에 인물 사진이 표시됨
  3. 실제 후보 원본 사진 — 인물이 다른 폰을 들고 촬영 중인 화면을 담은 사진
  4. 실제 후보 원본 사진 — 기내에서 손가락으로 폰을 쥔 채 화면을 촬영한 사진

## 검증 결과 (구현 디테일)

### 화면 경계 자동 검출 — 채택하지 않음

`VNDetectRectanglesRequest`를 기본 종횡비(0.5~1.0)와 튜닝된 종횡비(0.3~1.0) 두 설정으로 테스트했다.

| 샘플 | 결과 |
|---|---|
| 1 | 신뢰도 1.00으로 엉뚱한 사각형 검출 (오탐) |
| 2 | 정확한 화면 영역 검출 (aspect 0.513) |
| 3 | 신뢰도 1.00으로 엉뚱한 사각형 검출 (오탐, aspect 1.005로 실제 화면비와 크게 다름) |
| 4 | 검출 실패 (0개) |

4장 중 정확 검출은 1장(25%)뿐이며, 더 심각한 문제는 2장에서 **신뢰도 1.00으로 틀린 결과를 자신 있게 반환**했다는 점이다. 종횡비 필터(0.4~0.6 범위)로 오탐 2건은 걸러낼 수 있지만, 그래도 절반 이상의 케이스가 수동 개입을 필요로 한다.

**결론: 화면 경계는 자동 검출에 의존하지 않고 사용자가 4개 꼭짓점을 드래그해서 수동으로 지정한다.**

### 오브젝트(누끼) 자동 추출 — 크롭 후 범용 전경 인식으로 채택

원본 전체 사진에 사람 특정 인식기(`VNGeneratePersonSegmentationRequest`, `VNGeneratePersonInstanceMaskRequest`)를 실행한 결과:

| 샘플 | 사람 인식 커버리지 |
|---|---|
| 1 | 46.8% |
| 2 (가장 깔끔한 샘플) | **0% — 전혀 인식 못 함** |
| 3 | 12.6% |
| 4 | 16.2% |

가장 조건이 좋은 샘플 2에서조차 사람을 전혀 인식하지 못했다. 화면에 "찍힌 사진 속 인물"이라 반사·저화질·부자연스러운 자세 등으로 인해 실물 사람과 다르게 인식되는 것으로 추정된다.

이어서 사용자가 지정할 화면 영역만 크롭한 뒤 재검증했다:

| 샘플 | 사람 인식 (크롭 후) | 범용 전경 인식 (크롭 후) |
|---|---|---|
| 1 | 37.6% | 35.2% |
| 2 | 0% (여전히 실패) | **25.1%** |
| 3 | 17.3% | **56.5%** |
| 4 | 14.1% | 39.6% |

사람 특정 인식은 크롭 후에도 개선되지 않았지만, **범용 전경 인식(`VNGenerateForegroundInstanceMaskRequest` — iOS 사진 앱의 "피사체 들어올리기"와 동일 계열 기술)은 화면 영역만 잘라내고 나면 화면 속 콘텐츠를 하나의 안정적인 덩어리로 포착**했다. 원본 전체 사진에 바로 돌렸을 때 결과가 불안정했던 것은 폰 테두리·배경까지 뒤섞여 있었기 때문으로 판단된다.

**결론: 화면 경계를 먼저 수동으로 확정한 뒤, 그 내부에서 범용 전경 인식으로 자동 추천 마스크를 생성하고 사용자가 브러시로 추가/제거해 다듬는 "AI 초안 + 사용자 보정" 방식을 채택한다. 카테고리를 "사람"으로 특정하는 인식기는 사용하지 않는다.**

### 온디바이스 처리 가능 여부

위 모든 검증은 네트워크 호출 없이 macOS/iOS에 내장된 Vision 프레임워크만으로 수행됐다. 서버나 외부 API 없이 전체 파이프라인이 기술적으로 가능함을 확인했다.

## 제약 조건

- 화면 경계는 자동 검출을 사용하지 않는다 — 신뢰도가 높아도 틀릴 수 있는(확신에 찬 오탐) 실패 모드가 확인됐기 때문에, 사용자의 4꼭짓점 수동 지정을 기본 입력 방식으로 한다.
- "사람" 카테고리로 특정해서 찾는 인식기(`VNGeneratePersonSegmentationRequest`, `VNGeneratePersonInstanceMaskRequest`)는 채택하지 않는다.
- 범용 전경 인식(`VNGenerateForegroundInstanceMaskRequest`)은 반드시 사용자가 확정한 화면 영역으로 크롭한 이미지에 대해서만 실행한다. 원본 전체 사진에 바로 실행하면 신뢰도가 급격히 떨어진다.
- 최소 iOS 17 (`VNGenerateForegroundInstanceMaskRequest` 요구사항).
- 이번 검증은 샘플 4장짜리 소규모 스파이크로, 실제 사용자 사진의 다양한 분포를 대표하지 않을 수 있다. 정식 구현 과정에서 더 많은 샘플로 재검증을 권장한다.

## 완료 기준

- [x] 핵심 두 기능(화면 경계 인식, 오브젝트 누끼)에 대해 실제 Vision API를 실제 후보 사진 4장으로 실행해 결과를 확인했다.
- [x] 각 기능의 자동/수동 방식을 추측이 아닌 증거 기반으로 확정했다 (화면 경계: 수동 지정 / 오브젝트: 크롭 후 자동 추천 + 수동 보정).
- [x] 온디바이스 처리만으로 전체 파이프라인이 기술적으로 가능함을 확인했다 (네트워크·서버 불필요).
- [x] 발견된 리스크(확신에 찬 오탐, 사람 인식 실패)와 그에 대한 설계 대응을 문서화했다.

## 부록: 스파이크에서 확인한 핵심 API 사용 패턴

```swift
// 1. 사용자가 지정한 화면 영역(quad)으로 크롭한 CGImage를 handler에 넣는다
let handler = VNImageRequestHandler(cgImage: croppedScreenImage, options: [:])

// 2. 크롭된 이미지 안에서 범용 전경 인스턴스 마스크를 요청한다 (사람 특정 X)
let fgReq = VNGenerateForegroundInstanceMaskRequest()
try handler.perform([fgReq])
if let obs = fgReq.results?.first {
    let instances = obs.allInstances // 1개 이상, 배경 제외
    // 가장 큰 인스턴스(또는 사용자가 브러시로 지정한 인스턴스)를 팝아웃 대상으로 사용
    let mask = try obs.generateMaskedImage(
        ofInstances: instances, from: handler, croppedToInstancesExtent: false
    )
}
```

스파이크에 사용한 전체 프로토타입 코드는 세션 스크래치패드에서 실행 후 폐기했으며, 프로젝트 레포에는 포함하지 않았다 (버릴 코드 원칙).
