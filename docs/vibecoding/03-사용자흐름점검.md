# 3. 사용자 흐름 점검 — Peekpop

작성일: 2026-08-29
상태: 완료

## 요구사항

- [[01-구현가능성검증]] · [[02-기술스택선정]]에서 확정된 방식(화면 경계 수동 확인, 오브젝트는 AI 초안+조건부 브러시 보정)을 실제 화면 흐름으로 옮길 수 있어야 한다.
- 앱의 성패는 "사용자가 올바른 입력 사진을 준비하게 만드는 것"에 달려있다 — 첫 실행 시 촬영 가이드가 반드시 있어야 한다.
- 전체 흐름에서 모호한 분기가 없어야 한다 — 모든 단계에서 사용자가 다음에 뭘 해야 하는지 명확해야 한다.
- 로그인이 없으므로 흐름 안에 계정, 히스토리, 프로필 등의 개념이 등장하지 않는다.
- "속도 vs 안정성" 트레이드오프에서 옵션 1(완성도 있는 버전)을 선택했으므로, 자동 인식이 실패하거나 애매할 때도 사용자가 매끄럽게 수동으로 이어갈 수 있어야 한다 (스텝이 조금 늘더라도 잘못된 결과가 나가지 않는 쪽을 우선한다).

## 구현 디테일 (확정된 화면 흐름)

```
0. 온보딩 (최초 실행 1회만)
   예시 사진 1~2장으로 "이렇게 찍으세요" 안내

1. 메인 화면
   버튼: "사진 선택하기" (하나만)

2. 사진 선택
   iOS 표준 시트로 카메라 촬영 또는 앨범 선택, 1장
   → 선택 즉시 확인 절차 없이 3번으로

3. 화면 경계 확인
   - Vision(VNDetectRectanglesRequest)이 백그라운드에서 자동 시도
   - 성공 시: 그 결과로 4꼭짓점 위치를 미리 채움
   - 실패 시: 폰 화면 비율(세로로 긴 형태, 대략 1:2)의 기본 사각형을 사진 중앙에 배치
   - 사용자가 4꼭짓점 핸들을 드래그해서 위치 조정
   - "확인" 버튼 → 4번으로

4. 오브젝트 마스크 생성 (로딩)
   - 3번에서 확정된 영역으로 크롭
   - VNGenerateForegroundInstanceMaskRequest로 마스크 초안 생성
   - 마스크가 "그럴싸함" 기준을 만족하면 → 6번으로 바로 진행
   - 애매하면 → 5번(브러시 보정 화면)으로

5. 브러시 보정 화면 (조건부)
   - AI가 그린 마스크 초안이 오버레이로 보임
   - 브러시로 추가/제거 가능, 브러시 굵기 슬라이더로 조절
   - 지우개/전체 취소 가능
   - "완료" 버튼 → 6번으로

6. 합성 (로딩)
   - 마스크로 오브젝트 컷아웃 → 확대·재배치 → 그림자/블러로 입체감 추가
   - 최종 이미지 생성 (원본 사진 비율 유지)

7. 결과 화면
   - 완성된 이미지 미리보기
   - 버튼: "저장"(카메라롤) / "공유하기"(iOS 공유시트) / "다시 만들기"
   - 결과 화면에는 수정 버튼이 없다 — 마음에 안 들면 "다시 만들기"로 2번부터 다시 시작
```

### 주요 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| 화면 경계는 Vision 자동 시도 결과를 초안으로 미리 채우고, 사용자가 항상 확인/조정 | [[01-구현가능성검증]]에서 자동 검출이 신뢰도 1.00으로 확신에 찬 오탐을 낸 사례가 있어 결과를 그대로 신뢰할 수 없음. 다만 사용자가 어차피 눈으로 보고 고치므로, 틀린 초안이라도 출발점으로는 유용함 (마찰 감소) |
| 오브젝트 마스크는 그럴싸하면 브러시 화면을 건너뛰고, 애매할 때만 보정 화면 노출 | 화면 경계와 달리 마스크는 크롭 후 품질이 상대적으로 안정적으로 나왔고([[01-구현가능성검증]] 크롭 테스트 참고), 결과물이 "약간 거친 정도"에 그쳐 화면 경계 오탐보다 리스크가 낮음. 매번 보정 화면을 강제하면 마찰이 커짐 |
| 결과 화면에 "수정" 버튼 없음 | 두 단계(화면 경계·마스크) 중 어디를 고칠지 되짚는 구조가 복잡도 대비 이득이 적다고 판단, "다시 만들기"로 단순화 |
| 화면 경계 자동 인식 완전 실패 시 기본 사각형을 폰 화면 비율로 미리 맞춤 | 정사각형 기본값보다 드래그 거리가 짧아 마찰이 적음 |
| 온보딩은 최초 1회만, 매 사진 선택마다 반복 안내 없음 | 반복 안내는 마찰을 늘림 — 촬영법을 한 번 학습하면 충분하다고 판단 |

## 제약 조건

- 로그인이 없으므로 과거 결과물 히스토리/갤러리 기능은 이 흐름에 없다 (기기 카메라롤에 저장된 것으로 대체).
- 결과 화면 이후 인앱 보정(위치/강도 조절 등)은 MVP 범위에 없다 — 스티커 자동 배치, 결과 수동 보정, 과금 로직과 함께 다음 버전 과제로 남겨둔다.
- "그럴싸함" 판정 기준(마스크 커버리지 범위, 화면 경계와의 겹침 정도 등)은 이 문서에서 다루지 않는 구현 세부사항이며, 추후 화면 설계/API 설계 단계에서 구체적인 임계값으로 정의한다.
- 흐름 전체가 오프라인에서도 동일하게 동작해야 한다 ([[02-기술스택선정]]과 일치).

## 완료 기준

- [x] 앱 실행부터 결과 저장/공유까지 전체 화면 흐름이 분기 없이 순서대로 정의됐다.
- [x] 자동 인식이 성공/애매/완전 실패하는 각 경우에 대해 사용자가 다음에 뭘 하는지 명확하다.
- [x] 화면 경계와 오브젝트 마스크 각각에 대해 "자동 결과를 어떻게 다루는지"(초안으로 신뢰 vs 건너뛰기 조건)가 [[01-구현가능성검증]]의 리스크 평가와 일관되게 결정됐다.
- [x] 결과 화면 이후의 재시도 경로(다시 만들기)가 명확히 정의됐다.
- [x] 이 흐름을 그대로 화면 설계(4번 단계)로 옮길 수 있는 수준으로 사용자와 함께 확인했다.
