# 2. 기술 스택 선정 — Peekpop

작성일: 2026-08-29
상태: 완료

## 요구사항 (선정 기준)

- 로그인 없는 심플한 개인 서비스 컨셉과 맞아야 한다 (계정/서버 인프라 불필요).
- MVP는 완전 무료로 운영 가능해야 한다 — 서버/API 호출 비용이 없어야 한다.
- iOS 단일 플랫폼, SwiftUI로 개발한다.
- [[01-구현가능성검증]]에서 검증된 방식(화면 경계 수동 지정 + 크롭 후 AI 제안 + 브러시 보정)을 구현할 수 있어야 한다.
- "속도 vs 안정성" 트레이드오프에서, 지금은 완성도 있는 첫 버전(옵션 1)을 선택했으므로 개발 속도보다 결과물 품질을 우선한다.

## 구현 디테일 (선정된 스택)

| 영역 | 선택 | 비고 |
|---|---|---|
| UI 프레임워크 | SwiftUI | iOS 전용, 팀 결정사항 |
| 사진 입력 | `PhotosUI` (`PHPickerViewController`) + 카메라 캡처 | 앨범/카메라 둘 다 iOS 표준 시트로 처리 |
| 화면 경계 지정 | 수동 (드래그 가능한 4꼭짓점 핸들) | Vision 자동 검출(`VNDetectRectanglesRequest`)은 확신에 찬 오탐 사례가 있어 채택하지 않음 — [[01-구현가능성검증]] 참고 |
| 오브젝트 누끼 (자동 제안) | `VNGenerateForegroundInstanceMaskRequest` (Vision, iOS 17+) | 반드시 수동 지정된 화면 영역으로 **크롭한 이미지**에만 실행. 사람 특정 인식기(`VNGeneratePersonSegmentationRequest` 등)는 채택하지 않음 |
| 오브젝트 누끼 (수동 보정) | SwiftUI 제스처 기반 브러시 마스킹 (크기 조절 가능) | AI 제안 마스크를 초안으로 두고 사용자가 추가/제거 |
| 합성 (컷아웃, 확대/재배치, 그림자) | Core Graphics / Core Image | 별도 서드파티 이미지 처리 라이브러리 불필요 |
| 결과 저장/공유 | `PhotosUI`(저장) + `UIActivityViewController`(공유) | iOS 표준 시트 |
| 백엔드 서버 | 없음 | 전체 파이프라인이 온디바이스로 검증됨 |
| 외부 AI API (Claude API 등) | 없음 | 논의 중 한 번 검토했으나(비용·네트워크 의존·정밀 마스크 부적합) 기각 |
| 계정/로그인 | 없음 | 서비스 컨셉 자체가 무계정 |

## 제약 조건

- 최소 iOS 17 (`VNGenerateForegroundInstanceMaskRequest` 요구사항).
- 네트워크 연결 없이도 핵심 기능이 전부 동작해야 한다 (오프라인 완전 지원).
- Vision 프레임워크 중 "사람" 카테고리로 특정하는 요청(`VNGeneratePersonSegmentationRequest`, `VNGeneratePersonInstanceMaskRequest`)은 사용하지 않는다 — 검증 결과 신뢰도가 낮았음.
- 외부 AI API(Claude API 포함)는 MVP 범위에서 사용하지 않는다 — 네트워크 필수·비용 발생·로그인 없는 서비스 방향과 상충.
- 이후 버전에서 "하루 1회 무료" 같은 과금 로직이 추가되더라도, 계정 없이 기기 로컬 상태로 처리해야 한다 (스택 변경 없이 대응 가능해야 함).

## 완료 기준

- [x] UI 프레임워크, 사진 입력, 화면 인식, 오브젝트 누끼, 합성, 저장/공유 각 영역에 대해 구체적인 API/프레임워크가 하나씩 확정됐다.
- [x] 선정된 스택이 [[01-구현가능성검증]]에서 검증된 방식과 모순 없이 맞물린다.
- [x] 백엔드/외부 API 필요 여부가 명확히 "없음"으로 결론났고, 그 판단 근거(비용, 네트워크 의존, 서비스 컨셉)가 기록됐다.
- [x] 제약 조건(최소 OS 버전, 오프라인 지원, 사용하지 않는 API 목록)이 명시됐다.
